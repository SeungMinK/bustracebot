# BusTraceBot

설정한 노선과 정류장의 **실시간 위치·잔여 좌석**을 주기적으로 기록하는 가벼운 개인용 서버입니다. 별도 데이터베이스 서버 없이 SQLite 파일 하나로 동작합니다.

## 이 프로젝트가 하는 일

- 여러 출발 정류장과 목적 정류장을 한 번에 관측합니다.
- 차량이 정류장에 도착·출발할 때의 잔여 좌석과 시각을 저장합니다.
- 브라우저에서 날짜별 관측 결과를 확인하고, 노선·정류장·시간대를 변경합니다.
- 기본 프로필은 바로 시험할 수 있도록 채워져 있으며, 화면에서 원하는 프로필로 바꿀 수 있습니다.

## 빠른 시작

필요 사항: Node.js 18 이상, 그리고 [경기도 버스도착정보 API](https://www.data.go.kr/data/15080346/openapi.do)의 **일반 인증키(Decoding)** 입니다. 키는 무료 개발계정에서 발급받을 수 있습니다.

1. 프로젝트를 받습니다.

```bash
git clone https://github.com/SeungMinK/bustracebot.git
cd bustracebot
npm install
```

2. `.env.example`을 복사해 `.env` 파일을 만들고, `GBIS_SERVICE_KEY`에 발급받은 키를 입력합니다. `.env`는 Git에 포함되지 않습니다.

3. 정류장 매칭과 API 연결을 한 번 확인합니다.

```powershell
npm run collector:test
```

터미널에 매칭된 실제 정류장명·정류장번호·노선 순번이 표시되면 준비가 끝난 것입니다.

## 웹 화면 + 자동 수집

```bash
npm run build
npm start
```

브라우저에서 `http://localhost:8787`을 엽니다. `npm start`는 웹 서버와 수집기를 함께 실행합니다. 수집기는 활성 프로필의 평일·시간대에만 API를 호출하고, 다음 관측일까지 계속 대기합니다.

처음에는 웹 화면의 **관측 설정**을 열어 아래를 확인하거나 바꾸면 됩니다.

- 노선: 쉼표로 여러 노선 입력
- 출발/목적 정류장: 한 줄에 `표시명 | 정규표현식`
- 시작·종료 시각, 조회 주기

변경한 설정은 SQLite에 저장됩니다. 수집기는 재시작한 뒤 새 설정으로 정류장을 다시 찾습니다.

## 저장되는 데이터

- 기본 SQLite 파일: `data/bustrace.sqlite` — `.env.example`의 `BUS_TRACE_DB_PATH=./data/bustrace.sqlite`가 기본값입니다. 별도 DB 서버 없이 이 파일에 데이터가 적재됩니다.
- 웹 화면: 같은 SQLite DB를 읽어 차량·출발 정류장·도착/출발 좌석·목적지 통과시각을 표시합니다.

위치 데이터 갱신 주기에 따라 도착·출발 시각에는 오차가 있을 수 있습니다. 표의 좌석은 해당 상태가 관측된 가장 가까운 값입니다.

## 데이터 출처와 의미

경기도 GBIS 위치 API는 차량번호, 정류소 순번, 상태(도착/출발), 잔여좌석을 실시간으로 제공합니다. 수집기는 그 순간을 저장해 과거 표본을 만듭니다. 정류소와 노선 ID를 매일 직접 조회하므로 임의의 ID를 고정하지 않습니다.

## 설정과 확장

`settings`, `tracking_profiles`, `profile_routes`, `profile_stops` 테이블이 관측 대상을 관리합니다. 각 프로필에는 여러 출발 정류장(`source`), 하나 이상 목적 정류장(`destination`), 노선 목록, 평일/시간대/수집 주기를 저장합니다.

웹 화면 외에도 `GET /api/config`과 `PUT /api/config` API로 설정을 조회·변경할 수 있습니다. 정류장 이름은 실제 제공처의 이름과 비교할 정규표현식(`stationPattern`)으로 저장하므로 비슷한 명칭도 유연하게 매칭할 수 있습니다.

## 운영 팁

- 서버가 켜져 있고 절전 상태가 아니어야 관측이 이어집니다.
- 인터넷이 끊긴 시간의 데이터는 나중에 복구할 수 없습니다.
- API 키와 생성된 `data/` 폴더는 공개 저장소에 올리지 마세요.
